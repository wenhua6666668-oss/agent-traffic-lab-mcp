# Agent Traffic Lab Privacy Policy

Last updated: 2026-09-27

Agent Traffic Lab (ATL) provides a routing and execution layer for AI agents.

## Data ATL may process

When a user or agent invokes ATL, ATL may process the task text, tool inputs, routing metadata, execution status, provider selection data, latency and reliability signals, and Outcome records needed to route and execute supported tasks and improve routing quality.

ATL may also process standard service telemetry such as timestamps, request metadata, protocol events, error information, and security or abuse-prevention signals.

## How data is used

ATL uses this information to provide routing and execution, apply bounded fallback where appropriate, record Outcomes, maintain service reliability, debug failures, prevent abuse, and improve provider/tool selection.

ATL does not require an API key for the initial public MCP path described in the public documentation.

## Third-party providers and tools

ATL may route a task to eligible third-party providers, tools, or MCP servers. Data needed to perform that task may therefore be transmitted to the selected provider or tool. Those third parties may process data under their own terms and privacy policies.

Users should avoid sending secrets, credentials, highly sensitive personal information, or regulated data unless the selected provider and the user's deployment are appropriate for that data.

## Retention

ATL retains operational and Outcome data only as needed for service operation, security, reliability analysis, routing quality, and applicable legal obligations. Retention periods may vary by data type and operational need.

## Security

ATL uses technical and operational controls intended to reduce unauthorized access and unsafe routing. No internet service can guarantee absolute security.

## Contact

For privacy questions or requests, open an issue in the public ATL MCP repository or use the support channel listed in SUPPORT.md.
